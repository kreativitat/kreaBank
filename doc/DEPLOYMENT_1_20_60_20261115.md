# KreaBank 1.20.60 — native payment cancellation

Installed on `fin.degema.pt` on 2026-11-15 from
[`a137e18`](https://github.com/kreativitat/kreaBank/commit/a137e1834159c685a633cb314502c8fafb1d0866).
Baseline: 1.20.59; PHP 8.1.34 / Dolibarr 24.0.2.

## Result

Native invoice Cancel previously posted its form and displayed the supplier
list inside the payment modal. A real-browser negative control also showed
that a capture microtask could run before the native click handler created
the iframe, leaving its payment watcher unbound.

The watcher now binds in the next task. Recognized native payment Cancel is
intercepted before required-field validation, prevents submission and closes
only the native dialog containing that exact iframe. X and Escape retain their
existing behavior. Final submit-event evidence distinguishes prevented attempts
from genuine POST attempts: untouched/invalid cancellation leaves the list
unchanged; an earlier genuine attempt warrants one owned-row refresh with
analysis paused. Mixed attempts and duplicate close events cannot restart scans.

The wrong-bank invoice/salary/tax review and guarded account correction deployed
in [1.20.59](DEPLOYMENT_1_20_59_20261115.md) remain installed.
