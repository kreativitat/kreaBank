# KreaBank 1.20.61 — payment-bank column correction

Installed on `fin.degema.pt` on 2026-11-15 from
[`79238f2`](https://github.com/kreativitat/kreaBank/commit/79238f2807c89699523a9bf63412ffabd5a4864f).
Baseline: 1.20.60; PHP 8.1.34 / Dolibarr 24.0.2.

## Result

Possible wrong-bank movements now appear as a warning icon and an underlined
bank reference in the main row's Payment bank column. The reference opens the
existing reviewed account-change dialog. The separate other-bank section has
been removed from the movement selector. Reconciliation and creation remain
blocked while the account warning needs review.

List-only advice can identify an exact signed amount, currency and booking-day
coincidence in another owned account. This weaker evidence leaves Match empty;
it never becomes automatic matching evidence. An eligible same-account movement
takes precedence over a weak coincidence. Ambiguous, truncated, protected and
read-only results cannot authorize an arbitrary account correction. Existing
strong payment-account review and unattended matching rules are unchanged.

Successful correction returns to the collapsed list. It preserves the existing
movement and payment allocations; reconciliation remains a separate, freshly
reviewed action. The native payment cancellation fix from
[1.20.60](DEPLOYMENT_1_20_60_20261115.md) remains installed.
