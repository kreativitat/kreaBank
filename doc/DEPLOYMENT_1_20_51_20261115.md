# KreaBank 1.20.51 — production deployment

Deployed to `fin.degema.pt` on 2026-11-15 at 16:16:28 UTC from
[`2ec5cf2`](https://github.com/kreativitat/kreaBank/commit/2ec5cf2681eceff56f73a6bef4c45973d319638d).
The verified baseline was 1.20.50, on PHP 8.1.34 / Dolibarr 24.0.2.
**The separate Search row action is removed; the layers selector supports one or more existing movements.**

## Result

- The list has one existing-movement selector and the eligible native movement
  creation shortcut. More options remains absent. Native column filters and the
  selector's own text filter remain; old `mode=search` links canonicalize to
  `mode=batch` without executing a financial action.
- A single selected movement uses the ordinary signed `selected_native` review
  through `reconcileLine()`. It creates neither a duplicate native movement nor
  a one-member group. Eligible transfers, restricted-account reciprocal transfers
  and recognizable legacy imports retain this path, including installations
  without the optional group schema.
- Signed scalar source, target, booking day and linked financial/transfer facts
  are rechecked under existing locks. Completion removes only the current user's
  stale staged draft in the same transaction. Competing single/group choices,
  truncation and bounded-search exhaustion leave initial selection manual.
- Multiple movements retain the existing batch service, exact decimal totals,
  membership protections, historical projections and atomic undo. Group name and
  draft controls stay hidden for scalar selections. Other-account correction
  cards remain outside allocation controls and totals.
- Native Record payment remains on eligible proposed invoice rows. The removed
  expanded Search cards no longer provide a separate ambiguous-invoice payment
  chooser. Native invoice pages and the surviving selected-line workspace remain
  available. No legacy workspace controller or protected asset was changed.
- Cached reviews must match the displayed source namespace, row and bank account,
  as well as scope and expiry, before a confirmation can render.

  were reported as skips, not passes of their assertions.

  supported internal browser. Actual financial execution was tested only with
  disposable data. Production financial creation/reconciliation and source/database
  rollback execution remain untested by this deployment.
