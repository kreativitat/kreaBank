## Result

The reported existing unpaid salary now appears with **Record payment** in the
reconciliation list. Existing unpaid taxes use the same control when exact
remaining amount, date and meaningful identity qualify. Neither flow creates a
salary/tax parent or reconciles automatically. Invoice payment routes remain
unchanged; retired More/skip/quick-creation features remain absent.

`KreaBankPlannedPayment` keeps salary discovery outside unattended/bulk matching.
Native visibility and company ownership apply before exposing employee data.
Single-use actor/company-bound reviews expire after fifteen minutes; financial
POSTs recheck source, account, parent, allocations and identity under locks.
Existing banked/unbanked payments, other-account evidence, claims, restricted
accounts and active selections block creation. Native payment, bank attachment,
paid state and audit commit together; source stays pending for separate review.

The mobile correction resets native fixed row heights, preserves readable
evidence columns and versions its CSS URL by deployed modification time so
existing browser sessions receive the correction immediately. Earlier rendered failures and exact intermediate deployments are recorded in [1.20.54](DEPLOYMENT_1_20_54_20261115.md),
