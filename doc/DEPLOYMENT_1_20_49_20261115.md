# KreaBank 1.20.49 — production deployment

Deployed to `fin.degema.pt` on 2026-11-15 at 15:07:56 UTC from
[`625a557`](https://github.com/kreativitat/kreaBank/commit/625a557e1580fc8e46313d253fc0c12e9218f1e0).
The verified production baseline was 1.20.48. Production runs PHP 8.1.34 and
Dolibarr 24.0.2. **Source installation and the requested feature removal are verified.**

## Result

- Removed the reconciliation list's More options button, panel and all four
  `more_*` action handlers. Retired POSTs fail before workspace/service dispatch.
- Removed skip, quick tax creation and quick supplier-invoice creation from the
  selected-line workspace, service APIs and native adapter. Deleted the supplier
  dialog script and its unused CSS/choice logic. Generic quick entries reject
  unsupported types before schema, source or write access.
- The misleading drafts came from a provider that filtered by date/company/state
  without requiring amount or identity evidence. Remaining workspace draft advice
  now requires exact persisted amounts plus a complete counterparty name or a
  bounded real invoice reference. Native validation repeats the gate under locks.
- Search, batches, ordinary bank movements, existing invoice payments, existing tax
  matching, rules, reviewed differences and historical records remain supported.
  No financial action was submitted and neither reported invoice was changed.

## Deviations and limits

- The first CI run found an old assertion expecting the former creation-button
  wording. Updated that assertion; the pinned follow-up run passes both jobs.
- Server suites explicitly skip the two unavailable private bank-format fixtures
  and Excel normalization because PhpSpreadsheet is absent from the private source
  test tree. These were reported as skips, not executed passes.
- Database-backed suites were not run against production. Native creation,
  payment, draft validation and undo were not submitted as acceptance tests.
- Before this deployment, each of the two native supplier-invoice cards emitted
  `SyntaxError: Invalid or unexpected token` in the browser. Those existing native
  page errors were not changed by this task; changed KreaBank pages have no console
  errors.
- The installed historical `doc/RELEASES.md` remains preserved. Source rollback is
  prepared but unexecuted; database recovery remains untested.

Private receipts and desktop/mobile screenshots are retained outside the public
repository. The source and this sanitized deployment record are synchronized to main.
