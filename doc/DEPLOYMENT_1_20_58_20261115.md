# KreaBank 1.20.58 — native payment reference correction and live verification

Installed on `fin.degema.pt` on 2026-11-15 from
[`b237373`](https://github.com/kreativitat/kreaBank/commit/b237373c60a2b695f80c4f13b7c4f3f761a5c346).
Baseline: 1.20.57; PHP 8.1.34 / Dolibarr 24.0.2.

## Result

A blank optional payment number produces native `bank.num_chq = NULL`.
The verifier compared it strictly with an empty string and rejected a valid
native creation. Production request logs showed payment/bank creation followed
by verification and SQL rollback. Read-only checks confirmed the reported salary
remained unpaid, its statement pending and no payment, matching native debit or
creation audit retained. The failed attempt created no duplicate financial row.

The verifier now accepts only the native absent-reference representation for an
approved blank number. Native zero-reference semantics are explicit, with exact
text retained on the payment. All amount, date, account, method, ownership,
identity, duplicate and source checks remain unchanged. Private warnings contain
only a fixed failure stage and exception class, without raw financial data,
exception messages or SQL. The user-facing error and single-use reviews remain
unchanged.
